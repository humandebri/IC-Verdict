# W8A16 の計上命令数と x86 実行負荷

## 測定方法

`tools/bench_w8a16_metering.py` を Ubuntu 24.04 の GitHub Actions x86_64 ホストで実行した。対象はこのコミットからビルドした `verdict-engine.wasm`（SHA-256: `3bbb0359cd243985ccff6879ba003563cc7f7646f52b9d035deaac971c03799f`）。PocketIC v16.0.0-2026-09-18-03-28 で `bench_int8` を呼び、W8A16 SIMD カーネルの反復回数を 1、4、8、16 と変えた。各呼び出しの壁時計時間と PocketIC のプロセスツリーの CPU 時間を記録し、計上命令数に対する回帰直線の傾きで固定の入力準備・検証時間を除いた。

対照は同じ PocketIC 上の整数 XOR ループで、各反復に 257 個の依存した `global.set` と `i32.xor` を含む。ループ回数を校正し、各レベルで W8A16 とほぼ同じ命令数になるようにした。順序はブロックごとにシャッフルし、40 行を 10 ブロック、120 行を 6 ブロック測定した。下の比は、W8A16 の「計上命令数あたり増分時間」を対照の同じ値で割ったもの。区間はブロック単位のブートストラップ 95% 区間。

## 結果

| 実行・CPU | 形状 | W8A16 命令/MAC | 壁時計時間の比（95% 区間） | CPU 時間の比（95% 区間） | W8A16 増分時間/10億命令 |
| --- | --- | ---: | ---: | ---: | ---: |
| [Run 36112530374](https://github.com/humandebri/IC-Verdict/actions/runs/36112530374), Intel Xeon 6973P-C | 40×2304×768 | 0.6029 | 1.460 (1.221–1.670) | 1.889 (1.407–2.474) | 58.8 ms |
| 同上 | 120×2304×768 | 0.5953 | 1.268 (1.079–1.405) | 1.143 (0.943–1.353) | 54.0 ms |
| [Run 36113003722](https://github.com/humandebri/IC-Verdict/actions/runs/36113003722), AMD EPYC 7763 | 40×2304×768 | 0.6029 | 0.287 (0.278–0.296) | 0.293 (0.267–0.318) | 98.5 ms |
| 同上 | 120×2304×768 | 0.5953 | 0.295 (0.289–0.299) | 0.294 (0.284–0.307) | 101.9 ms |
| [Run 36113578696](https://github.com/humandebri/IC-Verdict/actions/runs/36113578696), AMD EPYC 7763 | 40×2304×768 | 0.6029 | 0.286 (0.276–0.298) | 0.263 (0.235–0.292) | 98.0 ms |
| 同上 | 120×2304×768 | 0.5953 | 0.289 (0.270–0.299) | 0.299 (0.282–0.314) | 99.8 ms |

Intel の対照は 40.3～42.6 ms/10億命令、AMD の対照は 342.5～345.9 ms/10億命令だった。つまり、対照を含めた相対評価は CPU に強く依存する。同じ Wasm バイト列でも、AMD では行列積の方が計上命令数あたりの負荷が小さく、Intel では大きい。AMD の傾向は別ランナーの再測定で再現した。Intel は 1 ランナーのみである。短い呼び出しでは CPU 時間が 10 ms 程度に丸められるため、特に Intel の 40 行の CPU 比は粗い。壁時計時間と 120 行の結果も確認する。

120×2304×768 のカーネル 1 回あたりの増分は Intel で約 6.8 ms、AMD で約 12.6～12.9 ms。IC 文書の「1 スレッドで毎秒 20 億 Wasm 命令」は処理能力目標であり、これを機械的に当てはめた約 63 ms/回より短い。この差をそのまま過大課金率とは呼べない。対照の速度も CPU によって大きく違い、命令数から実負荷への普遍的な換算率は得られなかった。

## 解釈の範囲

この実験は実 x86 CPU 上の PocketIC 実行プロセスを測っているが、GitHub ホストは仮想マシンであり、実 IC ノードの CPU 型番・クロック・他のスレッド負荷・合意処理を再現していない。測定対象は W8A16 カーネルの増分で、Laya 推論全体の負荷ではない。XOR は一つの対照処理であり、IC の全ワークロードの代表ではない。したがって、今回の結果は「約 11 倍の密行列積固有の過大課金」を立証しない。一方、計上命令数だけで実 CPU 負荷が決まるわけでもないことを、同一バイト列を使う 2 種類の x86 CPU で確認した。

再現手順と全呼び出しの生データはこのディレクトリの JSON と [計測スクリプト](../../tools/bench_w8a16_metering.py) に保存する。IC の処理能力目標は [公式文書](https://docs.internetcomputer.org/references/resource-limits/) を参照。
